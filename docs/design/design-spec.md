## 1. 位置づけ

- この文書は、デザインモックで決めた **色・文字・角丸・余白・部品の寸法** を、SwiftUI で実装するための基準としてまとめたもの。
- 数値はモック（iPhone 390×844pt）で使った値。pt としてそのまま使える。
- モックの表示データ（池袋 → 横浜、運賃、遅延内容）はすべてサンプル。
- 迷ったときは次の順で判断する：**要件定義書 > この文書 > モックの見た目**。

### 1.1 モックの画面一覧

| モック | 画面 | 主な要件 |
| --- | --- | --- |
| `Search` / `SearchDark` | 経路検索（駅入力・条件・履歴・お気に入り） | FR-SRC、FR-CND |
| `Main` / `MainDark` | 縦比較（検索結果） | FR-CMP |
| `Detail` / `DetailDark` | 経路詳細（縦タイムライン） | FR-DTL |

| `Status` / `StatusDark` | 運行情報 | FR-STS |

`mock/*.dc.html` は、キャンバスのエディタで表示するための形式（`support.js` が必要）。ブラウザで直接開いても正しく表示されない。見た目はキャンバスで確認し、数値の確認にはソースを使う。

## 2. デザインの方針

- ベースは HIG の標準部品（`NavigationStack`、`TabView`、`List` 相当のカード、セグメントピッカー）。
- **縦比較と縦タイムラインだけ独自の描画**にする（FR 10.1）。
- 画面の地は少し温かい灰色、カードは白（ダークでは濃い灰色）。**色味は路線の色に任せ**、アプリ自体の色は操作用の青 1 色に絞る。
- **角は丸く**（ユーザーの確認済み：「角を取って丸っこい方が親しみやすい」）。縦比較で決めた丸さを全画面の基準にする（4 章）。
- 路線は色だけで見分けさせない。**路線記号のチップを必ず添える**（NFR-A11Y-04）。
- 運行状況は **アイコン・色・文字** の 3 つで表す（NFR-A11Y-05）。

### 3.6 路線の色

## 5. 文字

### 5.1 書体

| 用途 | モック | iOS 実装 |
| --- | --- | --- |
| 日本語・本文 | Noto Sans JP（Web で代わりに使ったもの） | システムフォント（ヒラギノ角ゴ／SF Pro）。独自の書体は入れない |
| 時刻・数字 | Barlow（等幅の数字） | **案 A（推奨）**：SF Pro ＋ `.monospacedDigit()`。**案 B**：Barlow（SIL OFL）を同梱し、時刻にだけ使う |

- 時刻は必ず等幅の数字にする（カウントダウンや縦に並んだ時刻で桁がずれないように）。
- 案 B にする場合、フォントファイルは `DesignSystem` パッケージのリソースに入れ、Widget Extension・Watch からも読めるようにする。外部ライブラリではないので、NFR-05 には当たらない。

### 5.2 大きさ（Dynamic Type 対応）

モックの pt を、iOS の文字スタイルに対応させる。**実装ではスタイル名で指定し、pt を直接書かない**（NFR-A11Y-02）。

| モックの pt・太さ | 文字スタイル | 使う場所 |
| --- | --- | --- |
| 30 bold | `.largeTitle` | タブの最上位画面の見出し（経路検索、運行情報） |
| 32 bold 数字 | `.largeTitle` 数字 | 経路詳細の「8:10 → 8:52」 |
| 20 bold | `.title3` | 検索フォームの駅名 |
| 17 bold | `.headline` | タイムラインの時刻・駅名 |
| 16 bold | `.headline` | ナビゲーションのタイトル、主ボタン |
| 16 semibold 数字 | `.callout` 数字 | 縦比較の各列の「出発→到着」 |
| 15 bold | `.subheadline` bold | リストの行の見出し（路線名、履歴） |
| 14 semibold 数字 | `.footnote` 数字 | 縦比較の本体の時刻 |
| 13 | `.footnote` | 行き先、乗換時間、リンク |
| 12 | `.caption` | 補足、取得時刻、バッジの中身 |
| 11 | `.caption2` | 縦比較の駅名・目盛り、路線記号 |
| 10 | `.caption2` | タブバー（システムに任せる） |

- 縦比較の本体は列の幅が限られるので、大きい文字サイズ（アクセシビリティサイズ）では、ラベルの 2 行目（行き先など）を省き、列の上部にある要約を優先する。スナップショットテストで確認する（12.1）。
  - 列の要約は「出発→」「到着」、所要時間、乗換回数、運賃を 1 行ずつに組み替え、高さを 232pt に固定する。文字の大きさは要約で AX2、本体で AX1、目盛りで XXXL を上限にする（列の幅 約 107pt に収めるため）。
  - 本体の発着のラベルは駅名も省き、時刻だけにする。バッジと路線記号チップも大きくしすぎない（バッジ XL、チップ XXL まで）。
- アクセシビリティサイズでなくても（XXXL など）、縦比較の本体で時刻と駅名が列に入らないときは駅名を省き、時刻を優先する（時刻を「8:…」と切らない）。
- 縦タイムラインは、アクセシビリティサイズでは時刻が時刻の列（60）に収まらないので、時刻の列をなくし、時刻を駅名の上に出す。「駅の地図」や非対応の札は横に並べず、下に置く。
- Live Activity のカウントダウン（48／40／36pt）は、システムの枠に合わせて固定の大きさでよい。

## 7. 部品

### 7.1 路線記号チップ `LineSymbolChip`

- 地は `surface`。枠は 2pt で `Line.color`。文字は `textPrimary` の太字、数字用の書体。
- 高さ：縦比較 18、経路詳細 20、運行情報 22。最小の幅は 26〜30（高さ＋8〜10）。左右の余白 3。
- 角丸は `chip`（9）。
- 地を白にしない理由：山手線の黄緑のような明るい路線色でも、記号の文字が読めるようにするため。ダークでは地が濃い灰色になり、文字が明るくなる。
- VoiceOver では「山手線」のように路線名を読む（記号は読まない）。

### 7.2 経路バッジ `RouteBadge`

- 「早」「楽」「安」：20×20、角丸 `badge`、文字は 11pt の太字。1 つの経路に複数付いてもよい（FR-CMP-07）。並び順は、早 → 楽 → 安。
- 遅延：高さ 20、左右の余白 7、`capsule`。警告アイコン（12pt）＋「遅延」。`Route.hasServiceDisruption` が true のとき（FR-CMP-08）。
- 判定のロジックは `Domain` に置く（frontend.md 9.2）。

### 7.3 運行状況の札 `OperationStatusLabel`

- 高さ 24、左右の余白 8、`capsule`。アイコン 13pt ＋ 12pt の太字。色は 3.5 のとおり。
- 平常は地なし、文字は中くらいの太さ。

### 7.4 縦比較 `RouteCompareView`（FR-CMP）

モックの `Main` の構造：

```
┌ ナビゲーション：「池袋 → 横浜」／「9月26日(土) 8:05 出発」、右に条件ボタン
├ 並び替え：早い順｜乗換が少ない順｜安い順（セグメントピッカー）
├ 情報の行：左「IC運賃 · 8:04 時点の情報」、右「1–3 / 全5件 ›」
├ 列の要約（経路カード × 3）
│   104×104、角丸 lg、内側の余白 8
│   ├ バッジの行（高さ 20）
│   ├ 「8:14→8:48」 数字 16 semibold
│   ├ 「34分 乗換0回」 12（所要時間だけ太字）
│   └ 「¥836」 12
└ 本体のカード（角丸 xl）
    ├ 時間軸：左端の幅 38。目盛りのラベルは右寄せ
    ├ 目盛り線：gridline、1pt
    └ 列 × 3（幅 110。列の区切りも gridline）
        ├ 乗車区間の帯：列の左から 10、幅 22、capsule、Line.color
        ├ 路線記号チップ：帯の縦方向の中央。帯からはみ出してよい（幅 30）
        │   記号がなく路線名で代わりに表示するチップ（4 文字以上）は列の左端から置き、種別・行き先はチップの右に入るときだけ出す
        ├ 種別・行き先：列の左から 40、チップと同じ高さ
        ├ 発着の時刻と駅名：列の左から 40、その時刻の位置に（時刻 14 semibold ＋ 駅名 11）
        └ 乗換・待ち時間：帯の中心に 2pt の点線（connectorTransfer）
```

**時間軸の計算**（`Domain` に置き、ユニットテストの対象にする）

- 軸の範囲：全経路の最も早い出発 〜 最も遅い到着（FR-CMP-03）。上下に 12pt の余白を付ける。
- 1 分あたりの高さ：`(本体の高さ − 上下の余白) ÷ 軸の分数`。モックでは 52 分を 452pt に収めて 8pt／分。
- 目盛りの間隔は、隣の目盛りとの間が 40pt 以上になるように 5／10／15／30／60 分から選ぶ。
- 日付をまたぐ場合も、`Date` の差で計算する（`25:10` のような表記は使わない。FR-CMP-10、api-contract 2 章）。

**ラベルが重なるとき**

- 乗換駅で「着」と「発」のラベルの間が 32pt 未満のときは、2 つ目の駅名を省き、時刻だけにする（モックの「8:21 渋谷」「8:25」）。
- それでも重なるときは、発車の時刻を優先する。

**その他**

- 3 列を画面に固定し、4 本目以降は横スクロール（FR-CMP-02）。スクロールするのは列（要約と本体）だけで、時間軸は固定する。
- 列の要約と本体を合わせて 1 つのボタンにし、タップすると経路詳細を開く（FR-CMP-09）。VoiceOver では 1 列を 1 つの要素にして「経路1、8時14分発、8時48分着、34分、乗換0回、836円」のように読む（NFR-A11Y-03）。遅延があるときは最後に「遅延の影響あり」を足す。
- 読み込み中は、同じ骨組みのまま帯とラベルを灰色の角丸の四角にする（FR-CMP-11）。
