# 実データ接続後の固定評価区間

ユーザーが指定した初期テスト対象を `routes.json` に記録する。

| 区間 | 主な確認内容 |
| --- | --- |
| 東京 → 横浜 | 広域検索、複数候補が得られる場合の比較、運賃種別、重複排除 |
| 日比谷 → 神谷町 | 短距離検索、停車駅・時刻表の提供可否、直前・直後の再探索 |
| 梅田 → 心斎橋 | 関西圏の検索、駅の同定、取得できない機能の明示 |

梅田はまず **Osaka Metro の梅田駅** と解釈する。JR大阪駅・大阪梅田駅・東梅田駅・西梅田駅へ暗黙に置き換えない。日比谷は提供元の駅・路線対応を確認してCanonical IDへ解決する。

## 実行方法と合否の扱い

1. 実データの駅マスタで各駅を同定し、`canonicalStationId` を設定する。仮のProvider IDをCanonical IDとして使わない。
2. 実行対象の日時を日本時間のタイムゾーン付きで指定する。提供元の検索可能期間に合わせ、ケース一覧には日付を固定しない。
3. 同じ日時・条件で経路検索し、応答の `asOf`、出典、利用したデータ版を検証記録へ残す。
4. 公表情報または許可された提供元の結果と、発着駅・予定時刻・停車順・乗換・運賃種別を照合する。所要時間や料金は推測で期待値に設定しない。
5. 初回は出発指定、新幹線・有料特急なしで確認する。その後、逆方向・到着指定・日跨ぎを追加確認する。
6. capabilitiesに基づき、停車駅、時刻表、隣接検索、Live Activityの対応可否を確認する。対応を表明している機能の失敗は不合格。未対応機能を明示的に拒否できた場合は「未対応を確認」と記録し、「機能成功」とは数えない。

2026-09-26にRapidAPIで3区間とも **概算経路の接続確認に成功**。詳細は [接続確認記録](connection-check.md)。実ダイヤとの照合は未実施。この一覧は実交通データや自動テストの成功結果ではない。既存の架空データによる結合テストとは別に管理し、通常の `npm test` で外部APIを呼び出さない。
